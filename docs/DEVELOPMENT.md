# 維護說明

這是靜態網站，不需 npm 建置或後端查詢服務。查詢由瀏覽器中的 Web Worker 執行，道路資料依查詢內容載入。

## 檔案結構

| 路徑 | 用途 |
| --- | --- |
| `index.html`、`style.css` | 頁面與樣式 |
| `app.mjs` | 地圖、查詢操作與結果顯示 |
| `coordinates.mjs` | 座標轉換 |
| `location-tools.mjs`、`segment-parser.mjs` | 位置文字、樁號與路段辨識 |
| `map-export.mjs` | 地圖圖片匯出 |
| `pages/` | 背景查詢、資料載入與快取 |
| `engine/` | 里程計算、道路候選與路段處理 |
| `data/manifest.json` | 道路清單、檔案資訊與空間索引 |
| `data/` | 道路索引、查詢分片、gzip 與參考線資料 |
| `scripts/` | 資料打包與查詢比對工具 |
| `vendor/` | Leaflet 與授權文件 |

## 資料載入

開站先讀取程式與道路索引；支援解壓的瀏覽器使用 gzip 資料。GPS 藍點更新與拖曳地圖不會自動查詢樁號，顯示用的道路參考線也在按下按鈕後才載入。

完整資料不超過 150 KB 的小道路保留單檔，減少請求次數。較大道路先讀取原樁、資料範圍與分片索引，再依查詢選取線形：

- 座標查詢先用 1 公里網格選出道路，再以 500 公尺網格選取附近記錄。細格索引沿原始線段建立，包含 100 公尺邊界範圍。
- 樁號查詢只讀取里程範圍相符的線形；精確原樁且未指定側別時，不必下載線形。
- 路段查詢載入起迄範圍內的線形。側別查詢包含樁號前後各 5 公尺。
- 引道與雙向道路廊道會補齊其主線、參考線依賴，保留原本的候選判斷。

一般查詢以減少總下載量為目標。每個 JSON 與 gzip 檔不超過 500,000 bytes，但交會道路、長路段或大型單筆線形可能需要多檔，總量並無硬性上限。完整線形記錄不在分片處截斷；大型記錄用數個傳輸片重組，避免新增假的道路端點或改變里程。

`pages/client.mjs` 將查詢交給 `pages/query-worker.mjs`，由 `pages/model-loader.mjs` 載入資料，再呼叫 `engine/query-service.mjs`。

最多同時下載、解碼兩個資料檔。已載入的索引與分片會重用；快取以原始 JSON 大小累計，超過 24 MiB 時淘汰較早使用的資料。這個數值是快取淘汰門檻，不是瀏覽器記憶體上限。

## 修改程式與資料

- 省道雙向共用道路中心線與里程；橫向偏移不加入里程。引道沿用與主線對應的里程關係。
- 保留交會道路候選、資料缺口與推估標示。位置查詢的 60 公尺距離界線用於篩選候選，不代表定位精度。
- 側別僅作圖面示意。導航與分享連結應使用原樁號位置。
- 更新道路資料時，同步更新 JSON、gzip、檔名雜湊與 `manifest.json` 的檔案資訊及空間索引。
- 每條道路須保留完整的樁位校準、端點與引道關係。合併道路分檔後，依原始記錄順序還原資料，避免改變等距候選的排序。
- 引道附帶的車行線，以完整折線的外框篩選；保留與引道外框外擴 121 公尺範圍相交的線形。此範圍涵蓋位置到引道的 60 公尺，以及位置到車行線的 60.25 公尺判讀距離；若修改這些門檻，必須同步調整打包範圍。
- 保留手機版面與匯出選單的顯示條件。介面或功能變更時，同步更新使用說明與更新紀錄。
- 提交內容不應包含帳密、存取憑證或即時定位紀錄。

## 發布與檢查

以 GitHub Pages 發布時，選擇 `main` 分支、根目錄 `(root)`。所有資產、模組、Worker 與資料路徑都需支援 `/show_me_the_miles/` 子目錄。

程式中的 `/api/` 名稱由 `pages/query-api.mjs` 在瀏覽器內處理，沒有對應的伺服器 API。修改時應維持這個載入方式。

資料重新打包：

```sh
node scripts/build-shards.mjs
```

也可指定來源與輸出資料夾：

```sh
node scripts/build-shards.mjs ../previous-release/data ./data
```

與原分道路版本比對查詢結果及下載量：

```sh
node scripts/test-shards.mjs ../previous-release
```

文字辨識與樁號準確度檢查（只讀本機資料）：

```sh
node scripts/test-parser.mjs
node scripts/test-accuracy.mjs
```

錯置原樁的檢查與修正：

```sh
node scripts/correct-markers.mjs          # 只列出結果
node scripts/correct-markers.mjs --write  # 寫入道路索引
node scripts/build-shards.mjs data data /tmp/build-report.json
```

修正位置＝該里程的道路中心線位置，加上同向前後樁的側向偏移（依里程內插）；推估點與鄰樁的距離須符合里程差（±10%＋5 公尺），否則不寫入。原座標保存在樁位的 `corrected` 欄位，查詢結果顯示「修正樁位」，不視為官方樁位。取得公路局「省道里程坐標」新資料時，應優先以官方座標取代。

與公路局「省道里程坐標（里程牌標誌）」CSV 比對（Big5 或 UTF-8，預設只比對屏東縣，不修改資料）：

```sh
node scripts/compare-official.mjs 下載的檔案.csv
```

報告列出座標不同、新設或已移除的樁，以及官方 TWD97 與 WGS84 互相矛盾的列；兩者矛盾時網站採用 WGS84。

`test-accuracy.mjs` 以原樁座標反查樁號，並抽樣「樁號→位置→樁號」來回比對；也會列出位置與前後樁號矛盾、不直接採用的來源樁。

檢查範圍依修改內容決定：計算變更比對樁號、交會候選、端點與缺口結果；資料變更檢查 JSON／gzip 內容、雜湊、索引與跨片查詢；介面變更檢查電腦與手機操作。文件修改檢查文字與連結即可。

發布後以 GitHub Pages 部署結果及實際網址確認上線狀態。此儲存庫與 Cloudflare 版本分開維護。
